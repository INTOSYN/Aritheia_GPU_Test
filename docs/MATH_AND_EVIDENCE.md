# 数学条件与证据边界

场景运行回答“应用给出了什么结果”；精确探针回答“在已声明的精确算术条件下，计算与传输是否一致”。二者都不能单独定位某个晶体管，也不能给显卡永久健康证明。

## 精确乘加条件

A 每行至多 128 个非零值 ±2^e，B 为 ±2^-e，e 为 −8、0、8。每个非零乘积是 ±1；任何普通求和顺序下，部分和为绝对值不超过 128 的整数。这些输入、乘积、部分和及输出均可在 BF16、FP16、FP32、FP64 中精确表示。乘加分组和普通 split-K 不改变正确结果，零符号允许不同。

这一推导针对普通乘加实现及声明的输入，不适用于任意近似算法或无约束数据。矩阵形状本身不能资格化任意黑盒内核；当前 Torch/CUDA 路径仍要实测。契约既不证明正常训练的 BF16 误差为零，也不构成 softmax、归一化、反向传播、优化器或完整 Transformer 的数学证书。

## 0.5 固定参考

矩阵参考保存 68 个探针 × 8 个种子的输入摘要、完整输出摘要及每 4096 个输出值的摘要。参考由发布前的独立计算和健康设备复核后冻结；这些维护过程及机器日志不进入用户仓库。用户可验证参考文件、注册表和配套核心版本是否相互匹配。

用户运行时：

1. 主机准备固定输入，先核对发布者输入摘要；不一致是参考/主机问题，停止该项，不新增 GPU 异常结论。
2. 受测卡执行完整稠密 mm/bmm；输入往返分别逐元素核对。
3. 输出无损解码为 float32，小端编码，+0/−0 统一为零；比较固定完整与分块 SHA-256。
4. 发现不一致立即发出已核验事件并写入检查点，然后保存完整首错数组。后续失败保留已有 FAIL；缺失证据单独标注。

不进行 CPU GEMM 或参考 GPU 回算。SHA-256 是有限长度摘要，理论上存在碰撞；因此不能称为逐元素相等的绝对数学证明。对实际完整性检查，匹配被报告为本次预算内未观察到异常。

分块不匹配至少说明其中一个元素不同。若同块内有多个仍然合法的整数错误，摘要不能确定确切数量。`bad_values` 与 `bad_value_count_kind=lower_bound` 一起使用；NaN/Inf、非整数或越过 ±128 的值可以提高这个下界。输入和字节往返可精确计数。不得把下界用于推算故障概率或与旧版逐元素错误总数直接比较。

## 原生逻辑 SM 探针

BF16→FP32 `mma.sync.m16n8k16` 与 FP32 `fmaf` 链各最多累计 128 个 ±1 乘积。冻结范围固定为 chains=8、depth=8、四个种子、最多 4096 块；一块 1024 个输出。用户运行时只比较经过版本绑定的分块摘要。

只有起止 SMID 均非负且相同的块计入逻辑 SM 覆盖和逐 SM 不一致统计。迁移或无效块的不一致记入 `unattributed_bad_values`。逻辑编号允许不连续；完整覆盖要求观察到的不同有效 SM 数等于设备报告的 SM 数，且没有无效/迁移块。

起止相同不证明中间未抢占；逻辑 SM 编号不对应公开可确认的物理张量核。cuBLAS 场景计算落在哪些 SM 也不能由独立探针反推。

fatbin、参考与清单相互绑定。客户端验证它们的版本和摘要；不会把某个平台的构建结果视为所有未来架构均已验证。

## 状态与完成范围

已有合格 FAIL 优先于后续任何未完成状态；“存在异常”与“整个计划执行完成”是两个字段。没有执行全部请求场景、种子或原生通道时，不能仅凭已完成部分为整次任务返回 0。明确 `--probes-only` 或 `--no-native` 的用户选择会记录为范围限制。

68 个矩阵探针加 1 个字节往返是 69 项检查；12 个场景各有两档应用配置，是 24 次应用执行。两个原生核函数另列。检查元素总数包含输入、矩阵输出和往返字节，不能混称全部为矩阵输出。

矩阵形状为代表性工作负载：语言探针名义长度 256/1024，实际提示长度可能不同；尾批次、融合算法、注意力具体调用与反向传播不保证一一覆盖。所有应用都使用同一受测设备进行模型矩阵计算；主机执行数据准备、缓存读写、指标和摘要处理。

可选签名包是附加证据。签名证明来源和完整性，不证明数学参考正确；软件 fixture 不产生硬件通过结论。数据库接收内容标记为未独立核验的客户端报告，会话数不能视为独立物理 GPU 数。
