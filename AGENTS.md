# ComputeProof agent guide

Current distribution policy (0.5.0rc6): routine numerical comparison, references, exact/fixed probes, native driver loader, CUDA probe source/build script, and all twelve scenarios are public source. The routine client must not require computeproof-core or any private host extension. Do not restore the historical rc4 protected-core split. Only a separately reviewed diagnostic extension for an attention report may be distributed privately; downloading, executing and uploading its results each require explicit, separate consent. Source availability or a platform-neutral client wheel does not establish Windows GPU qualification.

Run `python -m computeproof doctor` before a GPU check, then use `python -m computeproof guided`. Report the selected GPU, the eight built-in scenario progress, optional-asset download state, exact-probe progress, native logical-SM coverage, output directory, and final exit status. Give a short progress update at meaningful stage changes and at least once per minute during a long run.

Never describe `INCOMPLETE` as passing. Preserve the distinction between an application metric, an exact numerical mismatch, and a logical SM identifier. Do not change GPU clocks, voltage, power limits, drivers, CUDA, or PyTorch. Do not expose raw UUIDs or `*.private.json`.

Respect the user's network choice documented in README. The guided 10-second countdown covers PBMC3k/SciFact data only. Qwen3.5-4B requires a separate explicit opt-in or --accept-model-download; --accept-download never authorizes a model download. Only pinned original Qwen3.5-4B BF16 weights are supported. Optional assets come directly from original repositories. Local dataset preprocessing records source hashes and dependency versions and is not an archived bitwise numerical oracle. Guided runs continue ready optional scenarios in the same session. Default online v3 records retain installation-scoped device hash, environment, protocol, preflight clock, requested budget and all 24 configuration completion states for normal and attention reports. Numerical/abnormal-SM diagnostics are automatic only for attention reports. Scores, decision fingerprints, detailed JSON and contacts require separate preview and final consent; name and email remain optional. Signed deep-case download, execution and result upload are distinct actions requiring the documented confirmations. Deep follow-ups never become evidence from the original natural run.

Keep --offline and --telemetry off documented in README and hidden from command help as requested. Preserve the eight built-in plus four optional-scenario workflow; normal optional-asset consent never authorizes diagnostic code execution. Rebuilding public native code requires instruction/reference requalification, not only a hash update. Preserve prior GPL grants and archived release evidence.
